## 2. 产品与玩法（当前设计）

### 2.1 核心循环

凌乱牌堆取卡 → 7 格合成台三连合成英雄 → 自动战斗守塔 → 击杀与拆塔拿分/金币 → 时代随时间推进。

唯一玩法数据源：`data/heroes.json`（勿在代码里重复维护英雄清单）。

### 2.2 已取消：关卡制

不再「打爆塔 = 过关进下一关 + 三选一奖励面板」。

相关实现见 `scripts/main.gd`（`TIME-ERA` / #72）：

| 规则 | 说明 |
|------|------|
| 时代推进 | 战斗时间驱动 `era_elapsed`；暂停/奖励遮罩不累计 |
| 时代时长 | `ERA_DURATION_SEC = [300, 480, 900, 1200, 1800]`（5 / 8 / 15 / 20 / 30 分钟） |
| 拆塔 | **只给金币 + 积分**，**不弹奖励面板**；敌塔按当前时代满血重建；清敌方单位，保留己方与牌堆/合成台 |
| 拆塔数值 | `TOWER_DESTROY_GOLD_BASE = 200`，`TOWER_DESTROY_SCORE_BASE = 100`（×时代） |
| 积分 | 消灭小兵击杀分 + 摧毁敌塔次数分 |
| AI 出兵 | 时代内按 `time_in_era_norm` 从少到多（`scripts/ai_spawn.gd` / `ai_spawn_config.gd`） |
| 失败 | 主要为己方塔被摧毁（未来时代拆塔也不强制通关胜利） |
| 清空台 | **无手动清空按钮**；台满卡住仍可自动扣金币/免费次数清空 |

文档：`docs/GDD.md`、`docs/ai-spawn-probability.md`。

### 2.3 重排

- 费用：`RESHUFFLE_COST = 200`（有免费次数优先）。
- 战斗中应可重排（含暂停）；点击必须有成功/失败可见反馈（toast）。
- 信息栏 `z_index` 高于暂停遮罩；重排有扩大触控热区（见 #69 / #76）。

### 2.4 热更对玩家的注意点

下载完成后须**从多任务彻底划掉 App 再开**（不是按 Home）。菜单「内容版本」应显示新版本号。

## 5. 热更新体系

### 5.1 原理

1. 客户端读 `MANIFEST_URL`：`https://mingge.asia/deck-and-merge/update/version.json`
2. 若远端 `version > installed_version`，下载 `pck_url` 的 `.pck` 到 `user://patch/`
3. 下次启动 `load_resource_pack` 覆盖资源后进主场景

详见 `docs/inapp-pck-release.md`。

### 5.2 硬规则（踩坑记录）

1. **`pck_url` 必须是 mingge 本站直链**  
   `https://mingge.asia/deck-and-merge/update/deck-and-merge-vN.pck`  
   **禁止**把 GitHub Release 写进 `pck_url`（302 / 国内网络会导致「下载失败」且进度百分比不出现）。
2. **`updater.gd` / `save_manager.gd` / `audio_manager.gd` 是 Autoload**  
   改它们通常要发**新 APK** 并 bump `BASE_VERSION`；普通玩法热更不要乱抬 `BASE_VERSION`。
3. 上行带宽可能很慢；大 PCK 推荐**分块 scp + 服务器 cat 组装**，勿长时间卡在单次 scp。
4. 导出：Godot 4.7.x + Android 预设：

```bash
tools/export_patch_pck.sh --version N --notes "…"
# 产出 artifacts/pck-vN/
```

### 5.3 现网路径

| 项 | 值 |
|----|-----|

| 目录 | `/var/www/deck-and-merge/update/` |

派「上传运维分队」时应通过 Cloud Agent `envVars` 注入 `MINGGE_SSH_*`，不要把密码写进 OPORD 正文或 git。

## 7. 指挥所（Mission Command）交接

### 7.1 角色

| 角色 | 含义 |
|------|------|
| 统帅 | 产品负责人（用户） |
| 参谋长 | 主对话 / COS agent，只指挥不改代码 |
| 分队 | 独立 Cloud Agent，一任务一队 |

技能目录：`~/.cursor/skills/mission-command-cloud/`  
API Key：`MISSION_COMMAND_API_KEY`（或环境等价配置）。

### 7.2 常设条令（必须遵守）

1. 参谋长**不直接修改**玩法代码 / 不本地当开发修冲突顶上；冲突与实现派分队。
2. 分队完成必须向 COS 发送以 `[MISSION-COMMAND REPORT]` 开头的战报（`report-to-cos.sh`）。
3. 每次向统帅汇报附 **7 字段任务表**（中文任务名与负责分队）：

   任务名 | 任务状态 | 任务描述 | 任务完成进度(0–100%，未经督察不得 100%) | 负责分队 | 证据链接 | 阻塞点/下一步  

   状态枚举：`未开始` / `执行中` / `已完成待督察` / `督察通过` / `阻塞` / `待决策`。

4. 热更 `pck_url` 只用本站直链（见 §5.2）。

任务板草稿可能在：`artifacts/mission-command/TASK-BOARD.md`、`STANDING-ORDERS.md`。
